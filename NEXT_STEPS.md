# Memory categories, movement, Home and authenticate flow

Memory now opens on **Movement**, with No Crouch, No Slide Fatigue, No Sprint Fire Delay, No Parachute, Fast Dive and Unlimited Fly together. Movement Tuning holds the fly, snowboard, slide-distance, speed and jump sliders. The other categories are **Weapon handling**, **Protection & view** and **Blueprints**. Wide layouts use two panels; narrower layouts stack related controls in one scrollable panel. Category navigation stays above the panels. `System/UI/MemoryTab.h` is shared by the actual Android menu and runtime preview. All original Memory controls and blueprint-tier colors remain available. Newly displayed slider labels start with their readable theme color.

**No Slide Fatigue** defaults off and saves as optional `ExtraMenu.NoSlideFatigue`; older configs load it as false. `System/Hooks/SlideFatigue.h` validates the 32-byte entry at `0x7C6976C` and the 16-byte recovery-time block at `0x7C69810` against the supplied 1.6.59 dump/library before installing the hook. It checks `SlideTackleComponent.m_IsLocalPlayer` at `0x38`, resets the local fatigue timestamp at `0x170`, and calls the original `LimitSlideTackle` with its original metadata argument. The normal routine recovers slide speed and idle duration. The configured recovery window (`0x44`), normal slide cooldown (`0x6C`) and movement tick remain under the game's control. If the original routine leaves the temporary timestamp unconsumed, the hook restores its previous bytes. Disabled and nonlocal calls pass through unchanged. A profile mismatch keeps the new toggle unavailable.

Home stays first. Its Home banner, frame-time metric and enabled-feature metric are removed. Only FPS and session time sit above the narrower performance graph, leaving music most of the width and the full available height. The song library is always open in a dedicated touch-scroll region, including on short landscape screens. The parent dashboard and music card can scroll without visible bars when necessary; scrolling across songs does not select them. The redundant full-width Drive-folder row is removed; the folder icon still changes the source.

Music editors open their integrated keyboard immediately, independent of the input backend reporting mouse or touch. Search/apply and cancel stay above the keys. Hardware typing, paste, clear, UTF-8 deletion and touch keys remain supported; an empty search can be applied to show the full library.

Drive replaces the Spotify/YouTube Music app controls. The default shared source is [MUSIC](https://drive.google.com/drive/folders/1Hd0PK3TO8rm4JkWfNZpwCmtHKvxgzh0T). Select **Home → Drive** to load it automatically, use the always-open **Library** to search/select songs, and use the folder button to paste another public Drive folder or audio-file link. No redirect URI or account sign-in is needed. Catalogs survive restarts. Selected tracks download to the app-owned hidden cache before MediaPlayer plays them; the stop button cancels a pending download. Refresh updates the song list and preserves the active selection when still present. A failed refresh leaves the previous catalog usable.

The Drive client accepts MP3, M4A, AAC, OGG, WAV and FLAC files directly inside the shared folder (256 tracks, 64 MiB per file, 192 MiB cache). It verifies HTTPS certificates with bundled Mozilla roots, limits redirects to Drive/Google download hosts and rejects preview/login pages and non-audio payloads. Public folder discovery uses Google's embedded-folder HTML, which can change; private folders, shortcuts, nested folder traversal and download confirmation/captcha pages are unsupported. Cached tracks are reused until evicted. Replace an edited song with a new Drive file when you need an immediate audio update; refreshing does not invalidate existing audio bytes.

Creamy UI sounds are original synthesized warm pops, droplets, soft swishes and a success chime. **Settings → Creamy UI sounds / Effects volume** controls them independently of music. The preview-sound button has been removed. The default effects level is 100%. Old `UIA1` preferences at the previous 28% default migrate to 100%; other saved levels and mute choices survive. `UIA2` preferences retain later manual choices, including 28%. Preferences are saved in the app's Music directory. Synthesis, OpenSL ES, network access, downloads and disk writes run off the render thread. Cue voices are bounded; rapid taps are limited, vertical scrolling is silent, and slider cues occur on edited release. Authentication cues follow stage changes once, including reduced motion.

Settings exposes **Custom FPS** (30–360) and **Ultra FPS override** (60–360). Frame-rate options are requested automatically, without a master unlock toggle. Reopen the game's Graphics / Frame Rate selector and choose an available level. The regular override applies to ordinary levels; the Ultra override takes priority for levels 5 and above. Changes apply as the game next reads/applies its frame settings; they do not manufacture frames beyond the device's render/display capacity. FPS choices are included in config SAV/LOD.

`System/Hooks/FrameRate.h` checks six readable, executable 1.6.59 entries against the supplied `libunity.so` before installing hooks. The encrypted `SetFrameRate` disk entry is excluded; overrides use the verified frame-value readers. The two older unconditional hooks at `SetUltraFrameRateDeviceInfo` are removed so they cannot invalidate the new compatibility check. A bounded background retry allows late initialization. The real signatures, including trailing IL2CPP method-info arguments, are preserved. No FPS integer is returned from a frame-level converter or Boolean lobby-capability method. Unlocking temporarily exposes frame levels through 9 and updates the verified device-info fields at `0x40–0x53`; disabling restores their original bytes. It does not change the neighboring current level or lobby-dynamic flag. Partial/unsupported installation leaves runtime overrides inactive. Settings preferences remain editable while support is pending, with a waiting status if an override is requested. Graphics-quality bypasses are not added.

Authentication now has a dedicated sound sequence: tactile press, soft button collapse, droplet morph/fall/splash, liquid rise, success, 700 ms rising suction, 150 ms compressed pulse, and a 1.95 s liquid shockwave starting with the white flash. Suction, explosion and reveal clip lengths read the existing named `AuthTiming` constants; animation timings are unchanged. The 350 ms calm beat cancels the startup audio channel before the loading reveal. Loading checkmarks cue at 25%, 50% and 75%, followed by a completion chime at 100% that can finish over Home.

Effects are original synthesized mono 48 kHz PCM cached once on the sound worker. The four-voice OpenSL ES pool separates startup sounds from ordinary UI feedback. Startup cancellation removes queued events and invalidates their epochs; hiding/canceling or muting stops playback, and a resumed screen does not replay missed cues. Reduced motion omits suction/explosion. Slow authentication waits quietly in the spinner and sounds follow the eventual visual stages. The existing effects mute and volume apply, independently of music. No external audio download or new sound-permission flow is required.

The ESP preview uses the exact Glayer3d Wiz mesh, skeleton and painted textures the user supplied. A 12-second skinned animation replaces the flat-image deformation during normal operation: foot-planted idle weight shifts with a wider hip sway and head glances, real eyelid blinks and smiles, a wave driven by wrist and elbow IK, anticipation, a hop and a landing. Because both arms are solved by IK targets anchored to their shoulders, the idle arms hang beside her hips with a bent elbow instead of the rig's straight A-pose, and the raised arm swings along an arc with a bent elbow and a palm-out hand so it never folds through the shoulder. Hair and chest use critically damped spring channels driven by the body's vertical acceleration, so the hair trails for about a quarter second and settles instead of hanging in the air, and the chest bounce is visible during the hop and again on the landing impulse. The model decodes once on a worker; GPU rendering uses a cached 320 × 512 target updated at most 30 Hz only while ESP is drawn. Overlay anchors follow the displayed skeleton. The previous PNG is retained only for initialization-failure fallback. Attribution, source hashes, the noncommercial license and reproduction instructions are in [WIZ_LICENSE.md](src/main/jni/Assets/WIZ_LICENSE.md).

The weapon configuration layout now matches the provided 1.6.59 dump: `IsDouble` is at `0x44`, the mount type at `0x48`, color text at `0x50`, camo data at `0x58`, description at `0x60`, and name at `0x68`. Name lookup runs once before applying a skin and skips a missing name. The previous layout targeted camo data when trying to change the name.

Authentication now uses the offscreen refraction compositor in the actual Android render path. The card and all glass callbacks are composited together before the suck-in transform. The shrinking card stays clear of viewport edges, and the explosion uses a continuous irregular front, bounded displacement, RGB source separation and a transparent warm interior. Production preserves the current game backdrop; the GPU harness uses a checkerboard to expose refraction. The old drawn explosion outlines were removed. The authenticate button has centered text and no icon. Its pill collapses into a circular spinner, and the same ring closes and morphs into the drop before the fall and splash. The glass surface fades with the morph and returns as the drop falls. The drop squashes into the impact instead of being replaced abruptly. The white fill uses one shared strip mesh through both rounded ends. The previous separate arc fans left triangular holes between each end and the center; exterior-only clipping checks did not detect those holes.

All existing named phase durations stay in `StartupState.h`. The calm interval is 8050–8400 ms; loading reveals at 8400 ms and settles at 8850 ms. The extra 750 ms is the settled review hold, ending at 9600 ms.

## Device configuration and inactive controls

The Configs tab saves device-local profiles and exports shareable JSON without license credentials or device identifiers. Import a shared JSON file by copying its text and selecting Import copied JSON; Android file-picker import has not yet been implemented. Profiles cover supported active settings. Fast Armor Plate, No Overheat, No Shake, Slide Distance, and Reset Guest are shown as unavailable until validated implementations exist. These switches are intentionally not activated from unverified dump offsets. Host builds and device verification are still required before merging to main.

Background screenshot reporting is disabled. User feedback requires explicit consent and HTTPS certificate checks. The current source has no user-facing consent enrollment, so automatic feedback uploads stay off.
